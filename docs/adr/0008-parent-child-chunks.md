# ADR-0008：子块检索，父块提供生成上下文

状态：已实施。

## 背景

单层切分要求同一个 Chunk 同时兼顾检索聚焦与上下文完整性。较小的 Chunk 更容易定位具体事实，却可能缺少前后的限制条件；较大的 Chunk 会增加不相关内容。采用父子块分离两种职责。

## 决策

1. 先从 IR 生成默认 1500 字、无重叠的父 Chunk，再在每个父 Chunk 内递归生成默认 500 字、80 字重叠的子 Chunk。字符数是切分口径，父块为目标长度；短标题/尾句合并时允许略超目标。短正文保留。表格为完整的父块与一个同内容子块。
2. 父块只保存到 MySQL `parent_chunks`，ID 为 `{doc_id}_p_{index}`。子块保持原 `chunks` schema 与 Milvus ID `{doc_id}_{index}`，映射存于新增 `chunk_parents` 表，通过外键连接子块检索 ID 与父块 ID。无需 ALTER 旧表或重建 Milvus schema。
3. dense / BM25 / RRF / rerank 均对比子块。启用父块回查时 rerank 请求返回整个候选池的排序，先应用分数阈值，再一次 JOIN 批量读取父块，按父块 ID 去重，最后取 `rerank_top_n`。避免兄弟子块占满候选名额。父块排名与分数使用首个（排名最高）命中子块，保留所有合格命中的子块 ID 供追踪。
4. Prompt、SSE 检索内容与引用正文使用相同的父块内容，引用 ID 使用父块 ID。关闭回查时沿用子块。compare 意图的文档多样性策略继续在子块候选阶段执行。
5. 默认开启 `use_parent_retrieval`，可通过环境变量、API 与前端开关覆盖。没有映射的旧 Chunk 回退到原正文；父块回查数据库异常会记录日志并降级为子块，所属文档不一致的映射不使用。
6. 重试先清理旧子块与父块，映射由外键级联清理；重新生成父块、子块和映射在同一 MySQL 事务内完成。删除 Document 同时清理两层与映射。`chunk_count` 保持可检索子块数的含义。

## 升级与验证

应用启动与批量入库的 `create_all` 会创建两个新增表。已有文档通过单篇重试或 `ingest_corpus.py --reprocess` 生成映射；后者保留文档 ID，仅处理 manifest 中的文档。切分参数变化必须重新入库才生效。

新增本地测试覆盖父子归属、短句保留、整表旁路、重复入库、删除级联、失败重试清理、旧文档回退、分数阈值、父块去重后截断和生成引用一致性。数据库生命周期测试使用启用外键的 SQLite，模型调用与 Milvus 写入替换为本地替身。

新增 `hybrid_rerank_parent` 消融档；原消融档显式关闭父块回查。在同一子块索引上对比扩展上下文的覆盖率。父块更大可能自然提升片段命中，这不等于检索排序变好；历史单层索引指标不可直接作为新索引的对照结果。

## 代价与限制

增加一次 MySQL 批量回查和父块存储；开启回查时需要返回更多 rerank 排序项，上下文通常更长。整表旁路仍可能产生很大的上下文，未在此决策引入表格裁剪。MySQL 与 Milvus 双写的跨系统一致性仍遵循现有状态机与重试机制。
